# Illusio

**Лаунчер Space Station 14 на Rust и Flutter**

[![ci](https://github.com/mel0k1/Illusio/actions/workflows/ci.yml/badge.svg)](https://github.com/mel0k1/Illusio/actions/workflows/ci.yml)
[![release](https://img.shields.io/github/v/release/mel0k1/Illusio?sort=semver)](https://github.com/mel0k1/Illusio/releases)

</div>

## Зачем

Официальный лаунчер SS14 написан на C# с Avalonia, и его интерфейс выглядит одинаково устаревшим на всех платформах. Illusio - это переписывание: логика переезжает в Rust, интерфейс - во Flutter. От этого две выгоды: ядро тестируется отдельно от интерфейса, а анимации и вёрстка ведут себя одинаково на Windows, Linux и macOS.

## Как устроен

- `core` - библиотека на Rust. Получает статус серверов и список хаба по протоколу RobustToolbox, входит в аккаунт центральных серверов SS14, скачивает и обновляет клиент - как классическими zip-сборками, так и по ACZ-манифестам с дельта-обновлениями, запускает игру. Наружу смотрит короткий C-интерфейс.
- `app` - приложение на Flutter в стиле Material 3 Expressive. Общается с ядром через FFI.
- `loader` - небольшая обвязка на C# по мотивам SS14.Loader из официального лаунчера. Собирается в CI и входит в готовые сборки: она поднимает движок из zip, монтирует сверху файлы сервера и zip-моды, загружает DLL-моды и применяет их Harmony-патчи к клиенту, запускает игру.

## Возможности

- плавающий нижний док: «Главная», «Сервера», «Настройки», «Моды»;
- два языка интерфейса - русский и английский - переключаются в настройках;
- «Главная»: избранные сервера, добавление по адресу и названию, редактирование и подъем избранного наверх, прямое подключение вставкой адреса, запуск реплеев-зипов content bundle;
- «Сервера»: живой список с основного и дополнительных хабов, поиск, онлайн у каждого сервера, цветовой пинг, описание с тегами, картой и раундом, ссылки сервера (discord, wiki, github, telegram), фильтры по языку, региону, RP-уровню, 18+, вайтлисту и числу игроков, скрытие пустых и полных;
- избранные сервера хранятся в конфиге;
- авторизация на `auth.spacestation14.com`, поддержка двухфакторной аутентификации, автообновление токена, вход гостем с настраиваемым именем, подмена имени при запуске, ссылки сброса пароля и повторного письма;
- несколько сохранённых аккаунтов: переключение одним касанием, выход, добавление, ссылка на регистрацию;
- «Моды»: ZIP-архивы из каталога модов включаются переключателем и монтируются в клиент как оверлей при запуске; DLL-сборки с классом `IllusioMod` применяются loader'ом через Harmony до старта клиента, у них отображаются имя, описание и версия из сборки; сборки без маркера сайдлоадятся как игровые моды через ModLoader движка; ресурс-паки с meta.json подменяют файлы контента по путям; дампер ресурсов выгружает весь контент сервера для подготовки своего пака;
- «Настройки»: тема (тёмная/светлая), язык (русский/английский), полноэкранный режим, vsync, скрытие пустых и полных серверов, дополнительные хабы, каталог клиента, свой движок вместо CDN, аргументы запуска, логи клиента, очистка кэша;
- SOCKS5-прокси для всего трафика лаунчера и игры: HTTP-запросы идут через прокси с авторизацией по логину и паролю, игровой UDP-трафик - через UDP ASSOCIATE релей, опционально клиенту передаются переменные `ALL_PROXY` и `HTTP_PROXY`; в настройках есть проверка прокси с замером задержки;
- сервер может потребовать принять политику конфиденциальности - Illusio показывает её перед первым подключением и не спрашивает повторно до смены версии;
- kill-switch: если версия лаунчера заблокирована или ниже минимальной в `info.json`, запуск блокируется с экраном обновления;
- подключение по ссылке `ss14://` из аргументов запуска;
- загрузка клиента с сервера:
  - классические zip-сборки по `download_url` с проверкой SHA-256;
  - серверы с ACZ (Automatic Content Zipper): манифест контента проверяется по BLAKE2b, недостающие файлы докачиваются блобами с zstd, каждый файл кэшируется по хэшу - повторное подключение после обновления сервера качает только изменённое;
  - движок нужной версии берется с `robust-builds.cdn.spacestation14.com` и проверяется по SHA-256 и подписи Ed25519;
- запуск клиента с токеном аккаунта и адресом сервера, как в официальном лаунчере;
- готовые сборки под Windows, Linux и macOS.

## Сборка

Нужны установленные Rust и Flutter.

Ядро:
```bash
cd core
cargo build --release
```

Приложение:
```bash
cd app
flutter create . --platforms=windows,linux,macos
flutter pub get
flutter run
```

Собранную библиотеку ядра положите рядом с исполняемым файлом приложения: `libillusio.so` для Linux, `illusio.dll` для Windows, `libillusio.dylib` для macOS.

Для серверов с ACZ рядом с приложением нужен каталог `loader`: его собирает `dotnet publish loader/Illusio.Loader.csproj` (нужен .NET 10 SDK). В готовых сборках из Releases он уже есть.

## Моды

Каталог модов открывается из настроек. ZIP-архивы монтируются в клиент как оверлей ресурсов, DLL-сборки применяются как Harmony-патчи. Для DLL-мода нужен публичный статический класс `IllusioMod` со статическим методом `Patch`:

```csharp
using HarmonyLib;

public static class IllusioMod
{
    public static string Name = "Мой мод";
    public static string Description = "Что он делает";
    public static bool Preload = true;

    public static void Patch(Harmony harmony)
    {
        harmony.PatchAll(typeof(IllusioMod).Assembly);
    }
}
```

Поле `Preload = true` применяет патчи до загрузки движка, иначе патчи применяются сразу и повторяются после загрузки контентных сборок, если цели ещё не существовали. Ссылаться на `Lib.Harmony` не обязательно: метод можно объявить без параметров, тогда инстанс Harmony создаёт loader.

DLL-сборки без класса `IllusioMod` считаются игровыми модами (как у Marseyloader'а Subverter): loader сайдлоадит их в клиент через ModLoader движка, постфикс на `ModLoader.TryLoadModules` вызывает `BaseModLoader.InitMod` для каждой включённой сборки.

### Ресурс-паки

Папки лежат в каталоге `respacks`, открывается из вкладки «Моды». Каждый пак — папка с `meta.json`:

```json
{
  "Name": "HiTech",
  "Description": "Замена текстур в стиле хай-тек",
  "Target": "hitech_fork"
}
```

Внутри - файлы, повторяющие пути контента: `/Textures/...`, `/Audio/...` и так далее. Включённые паки подменяют файлы по путям через постфикс на `ResourceManager.ContentFindFiles` — на месте канонического пути клиент получает файл из пака. Поле `Target` фильтрует пак по форку сервера (пустое значение - пак для всех).

### Дампер ресурсов

Переключатель во вкладке «Моды». При следующем подключении loader выгружает весь контент сервера в `dumps/<fork_id>` — готовая заготовка ресурс-пака: перечисление файлов через `ResourceManager.ContentFindFiles`, чтение через `ContentFileRead`. Дамп и ресурс-паки не работают одновременно.

## Релизы

Готовые архивы собирает workflow `release`. Порядок запуска:

```bash
git tag v0.4.0
git push origin v0.4.0
```

GitHub Actions соберёт ядро, loader и приложение под Windows, Linux и macOS, сложит всё в архивы и прикрепит их к релизу на странице [Releases](https://github.com/mel0k1/Illusio/releases).
